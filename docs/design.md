## 1. コンセプトと守ること

古いファイルがモンスターになる、ターン制のRPG。世界地図を歩き、戦い、町で売買し、依頼をこなす。倒したファイルは「回収待ち」にたまり、町の回収所で、まとめてごみ箱へ送る。

次の6つは、機能を足しても変えない。

1. **敵にできる条件を広げない。** 長く使われていない・使った形跡がない・システムの場所ではない、を満たすファイルだけが敵になる。AIは「守る側」にしか働かない。
2. **`ep.trash` は回収所の1か所だけ。** 戦闘中・店・依頼では、ごみ箱に触れない。本体の確認は、回収のときに1回だけ出る。
3. **AIは任意。** キーが無くても、全部の機能が遊べる。AIは、判断と文章を出すだけで、数値と結果はルールが決める。
4. **AIの返事は検証してから使う。** 決まった形・範囲・種類に合わないものは捨てて、手元の代わりを使う。
5. **送る情報は最小限。** AIに送るのは、ファイル名・拡張子・サイズ・放置期間だけ。ファイルの中身は読まず、送らない。
6. **画面の文章に（）の注釈を入れない。** 短く言い切る。

|---|---|---|---|
| 妖精（画像） | 思い出のかけら | 色褪せの羽 | 記憶の結晶 |
| ドラゴン（動画） | 竜の鱗 | 巨竜の牙 | 竜の心臓 |
| セイレーン（音楽） | 旋律の欠片 | 歌姫の髪 | 響きの宝珠 |
| ミミック（圧縮） | 古い釘 | 錠前 | 宝箱の金具 |
| 賢者（文書） | 古い紙 | インクの瓶 | 羽根ペン |
| ゴブリン（コード） | バグの欠片 | 錆びたネジ | 呪文の巻物 |

| かげ（その他） | 影のしずく | ほこり | 空白の石 |

- 個数は `1 + floor(敵Lv / 5)`。並は必ず1種、良は25%、稀はボスで必ず。
- 売値：並3G・良12G・稀60G（×個数）。持てる数は、各99個まで。

**装備**：武器・防具・アクセサリの3枠。
- 武器・防具は、今の8段階を引き継ぐ。店で段階が1つ上のものを買えるほか、**鍛冶屋で素材を使って作る**と「得意な相手」が付く。
  - 作る条件：`ゴールド 60×段階²`、その種族の並の素材 `4+2×段階` 個、良の素材 `段階` 個。
  - 得意な相手：使った素材の種族に与えるダメージが、1.15倍になる。
- アクセサリは、稀の素材で作る。効果はルールで決まる。実装では種族ごとに1つずつ（8種）：逃げやすさ（妖精）／会心（ドラゴン）／ヒール強化（セイレーン）／ゴールド増（ミミック）／経験値増（賢者）／素材増（ゴブリン）／ぼうぎょ強化（ガーディアン）／とくぎのMP減（かげ）。
- 装備の名前と説明は、AIが付けられる。性能には関わらない。

**画面**：メニューに「持ち物」を足す。素材・道具・装備を一覧し、装備の付け外しができる。

### 3.3 AI鑑定士【済】

敵にする前に、AIが「大事そうか」を見て、大事そうなものを守る。

**流れ**
1. 調査で候補が集まる。
2. 候補を40件ずつまとめて、AIに渡す（最大25回＝1000件まで）。
3. 返事の「大事そう度」が70以上なら、敵にしない。結果は覚えておき、同じファイルでは呼ばない。
4. 40〜69は、敵として出るが、戦闘の最初に鑑定士のひとことが出る。
5. 守られたファイルは、メニューの「守られたファイル」で、理由つきで確認できる。ひらく・場所をひらくもできる。

**AIへ渡すもの**：`{n: ファイル名, x: 拡張子, s: サイズ, i: 放置期間}` の並び。フォルダ名を送る設定は、初期値オフ。
**AIの返事**：`[{k: 番号, imp: 0〜100, why: 20字まで, tag: 税金|契約|思い出|仕事|身分|ゴミ}]`。形に合わないものは、その1件を手元の判定にする。
**手元の判定（AIなしでも常に動く）**：名前に「確定申告・契約・請求・領収・保険・年金・パスポート・免許・卒業・証明・履歴書・invoice・contract・tax」を含む → 90。拡張子が鍵・証明書・ウォレット系 → 95。「最終・final」を含む文書 → 60。AIの結果と手元の判定は、高いほうを採る。

> 未決（8章）：70以上を、完全に隠すか、敵として出して選ばせるか。

### 3.4 群れの戦闘（複数の敵）【済】

ねらい：パーティは**最大4人**（ヒーロー＋同行3人）。敵も、人数に合わせて**複数で同時に出る**。数は人数が目安だが、毎回ばらつく。

**出る数**（パーティの人数ごと）

| パーティ | 1体 | 2体 | 3体 | 4体 | 5体 |
|---|---|---|---|---|---|
| 1人 | 90% | 10% | | | |
| 2人 | 20% | 55% | 25% | | |
| 3人 | | 25% | 50% | 25% | |
| 4人 | | 15% | 30% | 40% | 15% |

- 敵の数の上限は「人数＋1」。人数より2体以上多いと、ほぼ全滅するので出さない（計算で、勝率0〜15%だった）。
- ヒーロー1人で2体が出るのは、ヒーローがLv5以上のときだけ。Lv4以下は、必ず1体。
- ボスの部屋は、ボス1体。パーティが3人以上なら、取り巻きが1〜2体つく。

**強さのつり合い**（計算の結果。全員「たたかう」だけの場合。下の「人数による補正」も参照）
- 敵の数＝人数：1人あたり約3〜4.5割のHPが減り、5〜6ターンで終わる。今の1対1と、ほぼ同じ。
- 敵の数＝人数＋1：約4〜5割減って、倒れる味方が出る。これを避けるため、**敵の数が人数より多いときは、敵のレベルの上限を1下げる**（約4割に収まる）。
- 敵ひとりあたりの能力は、今のまま。レベルの上限は「パーティの平均レベル＋1」。数が多いときだけ、上のとおり1下げる。

**群れの作り方**
- 先頭（リーダー）を、今までどおり選ぶ。残りは、**リーダーと同じフォルダのファイル**から集める。足りなければ、近い大きさのファイルから。同じ場所に住んでいた一味、という見え方にする。
- 全員に、戦う直前の確認（まだあるか・まだ古いか・使われていないか）を行う。外れた敵は、補充せずに減らす。確認は同時に行う。

**戦闘のしくみ**
- 味方と敵の全員を、すばやさ順（少しゆらぎ）に並べて、1人ずつ行動する。
- 「たたかう」と単体のとくぎは、狙う敵を選ぶ（左右キー／クリック）。選ぶとき、敵の名前と残りHPが見える。
- 全体攻撃を足す：とくぎ「ぶんまわし」（Lv3、MP5、全体に0.7倍）、道具「ばくだん」。
- 敵の狙いは、生きている味方から無作為。前衛は当たりやすい。ボスの強打は、狙う相手の名前を先に知らせる。ぼうぎょで半減できる。
- にげる：味方の平均すばやさと、敵の平均すばやさで決まる。ボスからは逃げられない。

**人数による補正**（実装で追加）
- 仲間が増えると、回復役やとくぎで、計算より強くなる。そこで、敵の能力を、人数が1人増えるごとに、HP+25%・攻撃+10% する（ソロは そのまま）。`file-quest/dev/balance.mjs` で、パーティ3〜4人の1戦が、6〜7ターン・勝率98%以上・減るHP 2〜3割になることを確かめた。

**数の見せ方**
- 戦闘中の単位は、その戦闘の「敵ぜんいんの合計サイズ ÷ 合計HP」で決める。敵のHPの合計が、敵のファイルの合計サイズになる。HP・MP・ダメージを、味方も敵も同じ単位で出す。

**報酬**
- 経験値とゴールドは、倒した敵ぜんぶの分を、ヒーローが受け取る。仲間は、ヒーローに合わせて育つ。
- 素材・回収待ち・依頼の進みは、敵1体ごと。

**AI**：二つ名・セリフは、リーダーだけをAIに頼む（呼び出しが敵の数だけ増えないように）。ほかの敵は、手元の表。

**画面**
- 敵は最大5体を横に並べる。数が多いほど小さく描く：1体224px、2体176px、3体144px、4〜5体は112px・96px。敵の下に、名前と残りHPの棒を出す。ボスだけ、今までの大きな絵。
- 味方は上に、小さな窓を最大4枚並べる（名前・HP・MP）。

### 3.5 酒場と仲間【済】

ねらい：NPCだけでも、本物のオンライン対戦でもない、中間の形。**友だちの分身が酒場に来て、フレンド申請をして、仲間に迎える。** サーバーは使わない。
ランダムに作ったダミーの旅人は出さない（最初の版では出していたが、2026-10-22 にやめた）。酒場にいるのは、取り込んだ冒険者カードの人だけ。物語の仲間は、10章の「部」で足す。

**町の「酒場」**（どの地図の、どの町にも出る）
- 町のメニューの「酒場」。見出しは「この町に訪れた人物」。
- 取り込んだカードの人が、全員、一覧に出る。日付や町では変わらない（カードは、友だちが自分で渡したものなので、いつでも会える）。
- カードが1枚も無いときは、「冒険者カードを取りこむと、その人の分身が来てくれる」と案内する。
- 一覧の下に「カードを 取りこむ」「フレンド」。人を選ぶと「はなす」「フレンド申請」「くわしく」ができる。
- 「はなす」は、その人のひとことを言うだけ。親密度や1日1回の制限は無い。

**フレンド申請**
- 申請は、必ず受け入れられる（カードを渡した時点で、承認したとみなす）。フレンドは最大12人。

**仲間に迎える**
- フレンドのうち最大3人を「同行」にできる（ヒーローと合わせて、パーティは最大4人）。「酒場」→ フレンド →「同行をお願い」。
- 同行中は戦闘に加わり、経験値を分け合う。「ここで別れる」で、いつでも外せる。
- 絆の段階が上がるごとに、強い技を覚える。カードの人は、レベルからも段階が決まる。
- 能力：カードのレベルとヒーローのレベル+2の、低いほうに合わせる。
- 古いセーブにいる NPC のフレンド（kind が "npc"）は、そのまま残る。能力はヒーローのレベル−1。

**冒険者カード**（本物の冒険者を呼ぶ仕組み）
- メニュー「冒険者カード」→「自分のカードを出す」：1行の文字列（コード）が出る。友だちには、チャットなどで送る。
- 「友だちのカードを取り込む」：コードを貼ると、その人の分身が、酒場に来るようになる。酒場の中からも取り込める。
- カードの中身：名前・役割・レベル・能力・とくぎ・ひとこと・種（絵と口ぐせを決める数）。大きさは1KB以内。
- 安全：貼られたコードは、決まった形か・文字数・数値の範囲を検査する。能力は、レベルから計算できる上限で切り詰める（改ざんしても強くなれない）。文字は画面に描くだけで、HTMLとしては扱わない。
- 通信もファイルの権限も要らない（コードの受け渡しは、利用者が行う）。

**戦闘（同行がいるとき）**
- 3.4の群れの戦闘のとおり。仲間の行動は、「おまかせ」か手動（設定で選ぶ）。仲間が倒れても、ヒーローが生きていれば続く。ヒーローが倒れたら負け。

**AIの役目**：酒場では使わない（旅人の性格づけは、ダミーの旅人をやめたので無くした）。

### 3.6 AIで敵の技をつくる【済】

- ファイル名から、技名と効果を作る。例：`最終版_v3.pptx` →「最終版の呪い」。
- 効果は、決まった部品だけ：`ダメージ(倍率0.8〜1.6)`／`自分を回復(10〜25%)`／`眠らせる`／`めくらまし`／`ガード`／`吸収(倍率0.6〜1.2)`。部品の外・範囲の外は、切り詰める。
- 技の出る頻度は、今のまま（通常28％、ボス35％）。
- 1ファイルにつき1回呼び、結果を覚える。失敗したら、種族の技のままにする。

### 3.7 AIで依頼をつくる【済】

- 見つかったファイルの件数・種族・フォルダ構成から、依頼文と達成条件を作る。
- 条件は決まった型だけ：種族・件数・合計サイズ・ボス・ぼうれい・勝利数。必要な数の1.5倍以上、実際に敵がいる依頼だけを採る。
- 達成の判定は、ゲームが機械的に行う。ほうしゅうは、型と必要数から計算する。

### 3.8 勇者・仲間の見た目【済：1.0.6】

ねらい：勇者の見た目を、プレイヤーが選べる。友だちから見える姿も、その人が選んだものになる（カードを出した時点の姿）。

- **見た目は5つの選択**：髪型（6）・髪の色（8）・肌の色（5）・服の色（8）・かぶりもの（4：なし・とんがり帽子・かぶと・リボン）。番号の組み合わせで決まる（7680通り）。素材も通信も要らない（ドット絵を計算で作る。`hero.js`）。
- **絵**：人型の16×16。役割ごとの持ちもの（剣・杖・虫めがね・短剣）が付く。勇者は剣。
- **選ぶ画面**：冒険者カードのメニュー「すがたを かえる」。項目を選ぶたびに、次の候補になり、右の大きな絵がその場で変わる。「おまかせ」「これで けってい」。はじめて起動したときにも、名前といっしょに選ぶ。
- **描くところ**：地図（左右の向きに合わせて反転）・戦闘の味方の窓・地図の仲間の窓・酒場・フレンド・取りこんだカードの一覧（右に大きな絵）。
- **カードに載せる**：カードに見た目の番号（`lk`）を足した（版は1のまま。古いカードも読める）。出した時点の姿が、友だちに伝わる。
- **安全**：カードのコードは信用しない。見た目の番号は、5つの整数で、それぞれ範囲の中、を検査する。おかしければ、カードは拒否せず、種から決めた姿にする。数字だけなので、文字や画像は入らない。
- **古いカード・見た目の無いフレンド**：種（`seed`）から決めた姿が出る。
- **同じ人の新しいカード**：名前・役割・種が同じなら同じ人。取りこむと、見た目・ひとこと・レベルが新しくなる（フレンドの記録も）。
- **セーブ**：`look`（5つの番号）。古いセーブは、種から決めた姿が入る。リセットしても残る。
- **島**：島の形の種（`islandSeed`）を、選んだ冒険の地のパスから決める。同じフォルダなら同じ島、別のフォルダなら別の島。冒険の地を選びなおすと、島も作りなおす。
- テスト：`unit.mjs`（番号の検査・全組み合わせの絵・ふちどり・古いカード・盛ったカード・島の種）と、`play.mjs`（見た目を選ぶ・出したカードに載る・友だちの見た目がカードのとおり・戦闘の味方に見た目がある）。`sprites.mjs` が、見本画像 `file-quest-heroes-preview.png` を作る。

### 3.9 弾よけ【済：1.4.0】
ねらい：戦闘が「たたかう・たたかう」の くりかえしで 単調になるので、敵のこうげきの番を、操作する場面にする（実際に遊んだ声：Undertale のような簡素な弾幕に したら 面白いのでは）。
- 勇者がねらわれたときだけ。ふだんのダメージ（敵のこうげき・勇者のまもり・ぼうぎょ・属性で決まる）を 先に計算し、弾よけの結果で 受ける量を決める。1発ごとに ふだんの半分・上限は 1.5倍・当たったあとの 0.7秒は 当たらない。うまくよければ 0。ふつうに遊ぶと 1〜2発（ふだんと同じくらい）。
- 枠は 260×200。ハートは 矢印・WASD で動く（速さ150）。時間は ふつう 3.7秒（強い技・ボスは 長め・敵が3体以上のときは 2.6秒に 短く。長くても5.5秒）。
- 弾の出かた：雨（上から ばらばら）・横ぎり（すきまのある列。すきまは前から遠くない所）・ねらいうち（いまのハートをねらう）・輪（はじけて広がる）・うずまき。種類ごとに 2つ（先頭がいつもの。強い技・ボスは 2つとも重ねる）：画像＝輪・ねらい／動画＝雨・横ぎり／音声＝うずまき・雨／圧縮＝ねらい・横ぎり／実行＝横ぎり・輪／書類＝雨・輪／そのほか＝雨・ねらい／コード＝そのつど ちがう。
- ねむり・めくらましの技（画像・音声・AIの技）は、勇者がねらわれたとき 当たったときだけ かかる（かわせば かからない）。
- 仲間がねらわれたとき・勇者がねむっているときは、いままでどおり 自動で決まる（弾よけは 出ない）。
- Esc（X・Backspace・M も）で とばせる。とばすと、ふだんのダメージを そのまま受ける。設定『戦闘で 敵のこうげきを 弾よけで よける』で オフにできる。
- 作り：`bullets.js`（画面を持たない。同じ種なら 同じ弾の出かた）。`autoDodge`（自動でよける人）で、どの弾の出かたも よけられること（動かないと当たる・自動なら ほぼ かわせる）を 試験している。見本は `file-quest-bullets-preview.png`。
- これから：弾の出かたを ふやす（レーザー・ゆっくり動く大きな弾・枠が動く）、ボスごとの専用の出かた、ミス・ブラインド中の見え方、マウスでも動かせる。

## 4. データの形

セーブは `ep.storage` の `save`。変更するときは `v` を上げ、読み込み時に古い形を新しい形に直す。

```
save (v2)
  v, seed, x, y, home
  lv, exp, hp, mp, gold, kills, freed, steps
  roots[], cleared[], spared[], log[]
  quests { offers[], active[], done }
  inv {                         # 所持品（新規）
    mat   { <素材id>: 個数 }
    item  { herb, herb2, ether, smoke, bomb }
    gear  [ { id, slot, tier, affinity, name } ]
  }
  equip { weapon: <gear id>, armor: <gear id>, acc: <gear id|null> }
  friends [ { id, kind: "card" (古いセーブには "npc" も), name, role, lv0, persona, quip, seed, bond, since, hp, mp } ]   # フレンド（新規）
  party   [ <friend id>, ... ]                                                              # 同行（最大3人。新規）
  cards   [ { id, name, role, lv, stats, skills, quip, seed } ]                             # 取り込んだ冒険者カード（新規）
  shop  { dayKey, special }                                # 日替わり（新規）
別の保存：pool（敵の候補）、pending（回収待ち）、lore（AIのセリフ）、appraisal（鑑定結果。ファイルの鍵→{imp, why, tag}）
```

古い `wep`・`arm`（段階の番号）は、`gear` に変換して、`equip` に入れる。

## 6. AIの使い方（まとめ）

| 用途 | いつ | 送るもの | 返事 | 保存 | 失敗したとき |
|---|---|---|---|---|---|
| 二つ名・セリフ【済】 | 戦闘の直前 | 名前・種族・Lv・サイズ・放置期間 | title・taunt・last | `lore`（200件） | 手元の表 |
| 日誌【済】 | 宿屋 | 数字だけ | 文章 | なし | メッセージ |
| 鑑定【済】 | 調査のあと | 名前・拡張子・サイズ・放置期間（40件ずつ） | imp・why・tag | `appraisal` | 手元の判定 |
| 敵の技【済】 | 戦闘の直前 | 名前・種族・Lv | 技名・効果・倍率 | `lore` に同居 | 種族の技 |
| 依頼【済】 | 調査のあと | 件数・種族・サイズの集計 | 依頼文・条件 | `quests` | 手元の依頼 |
| 部の物語の設計図【案】 | 部をつくるとき（1回） | 舞台の種類・各章の型とボスのファイル名など・仲間・これまでのあらすじ | 設計図（10.6） | 部のデータに凍結 | テンプレートで同じ形 |

- 費用を抑える決まり：まとめて送る（鑑定）、結果を覚える、1回の調査で呼ぶ回数に上限（25回）、同時に2つまで。
- 呼び出しの失敗が続いたら、しばらくAIを止める（今のとおり）。キーが使えない（401・403）ときは1時間止める。キーやモデルを設定で変えたら、止めていたのを解く。

**実機で分かったこと（1.0.2）**
実機のログ（`%APPDATA%\com.neoneptunity.explorerplus\logs\mod.neo.file-quest.log`）で、AIの通信は成功（200）しているのに、毎回「返事を読めない（bad-json）」で捨てていた。
- **原因**：Haiku 5.5・Sonnet 5.5 は、考える機能が**標準でオン**。考えた分も `max_tokens` に数えられるので、小さい上限（二つ名は380）だと、答えのJSONが途中で切れるか、文章が空になる。
- **直し方**：`output_config: { effort: "low" }` で考える深さを低くし、上限を十分に取る（二つ名1500・日誌1500・鑑定6000・依頼2500。上限は、使った分しか料金がかからない）。文章のブロックだけを読む。返事に前後の説明や ```json の囲みがあっても、閉じたJSONを取り出す。切れた配列は、書けていた分だけ使う。
- **見えるようにした**：読めなかったときは、終わり方・出力トークン数・中身の種類・返事の先頭を、ログに残す。コマンド「AIの接続を確かめる」と、「つよさ」の最後のページで、成功・失敗の数と理由が見られる。
- テスト：`unit.mjs`（取り出し・切れた返事・考えるだけの返事・HTTPエラーの理由）と、`play.mjs` の偽のAI（考えるブロックが先に付く実機に近い返事。頼み方が effort low・上限1000以上であること）。

**AIの費用と、冒険の地の大きさ（1.0.3）**
- 鑑定は、1回に40ファイル、1回の調査で最大25回（最大1000ファイル）。フォルダの大きさに歯止めが無いと、大きなフォルダを選ぶたびに、この25回を使い切っていた。
- そこで、**冒険の地の大きさを検査して、AIを呼ぶ前に断る**。数えるのは、敵になれる候補（古いファイル。システムの場所・最近使ったもの・アクセスの形跡があるものを除いたもの）の数と合計サイズ。
  - 下限：30個かつ200MB（小さすぎて冒険にならない。10.2の部になる条件と同じ）。
  - 上限：600個（鑑定は最大15回。調べるのも重くならない範囲）。設定「冒険の地の上限／下限」で変えられる。
  - 調べている途中で、候補が上限の3倍（1800個）を見つけたら、そこでやめる（広すぎるフォルダを、最後まで調べない）。
  - 断るときは、数と理由を言って、選びなおしてもらう。最初の一度目は、通る場所を選ぶまで。ふだんは、選びなおすか、前の冒険の地にもどるかを聞く。
  - 調べた結果の最後に、AIの鑑定が何回だったかを出す。
- テスト：`unit.mjs`（境目の値・途中でやめたとき・壊れた設定・断る文）と、`play.mjs --gate`（上限をこえた場所を選ぶと、AIの鑑定0回で断られ、選びなおして通る）・`--gate=abort`（途中でやめる道）。

**放置の年数と、日付が分からないファイル（1.0.5）**
- 実機で「46年放置のファイルが見つかった」と出た。今年から46を引くと1980年。更新日時が **1980-01-01**（zip や古い形式の「日付なし」の既定値。1970-01-01 のこともある）のファイルを、本当に1980年から放置されていると数えていた。
- **安全の問題でもあった**：zip から展開したばかりのファイルは、更新日時が1980年でも、このPCに来たのは最近。更新日時だけで見ると、来たばかりのファイルが敵（討伐対象）になっていた。
- 直し方（`idle.js`）：更新日時が**1990年より前**のファイルは、日付が分からないものとして扱う。放置の起点は、**このPCに来た日時（作成日時）**にする。
  - 作成日時も新しい（放置の日数に届かない）・分からない → 古いとは言えないので、敵にせず守る。
  - 作成日時を調べない設定（アクセス日時を見ない）のときは、日付が分からないファイルは守る。
  - 敵になるのは、このPCに来て日数がたったものだけ。敵になったものは、起点（`since`）を覚えていて、画面・AIへの情報・ぼうれいの判定が、全部そこから数える。
  - ふつうの更新日時のファイルは、これまでどおり更新日時から数える（OneDriveの同期で作成日時が新しくなるファイルを、ぜんぶ守ってしまわないため）。
- 候補の見積もり（1.0.4）では、日付が分からないファイルは数えない（本番の調べで、来て久しいものだけが加わる）。
- 戦う直前の再確認でも、同じ数え方で確かめなおす。前の版で調べた古い記録（`since` が無い）も、戦う前に直る。
- テスト：`unit.mjs`（日付が分からない値・起点の決め方・「46年」の再現と修正・ぼうれいの判定）と、`play.mjs`（日付なしで来て久しいファイルは敵になり、起点は約900日前／昨日来たもの・来た日時が分からないものは守られる／画面に10年以上の放置表示が出ない）。

**冒険の地の候補を、機械的に見つける（1.0.4）**
- 選ぶ人が大きさを知らないまま選んで、あとで断られる、をなくす。ゲームが先に調べて、**検査に通る場所だけ**を、大きさの目安つきで見せる。選ぶだけで、冒険の地が決まる。
- やり方（`discover.js`と`index.js`の`discoverCandidates`）：クイックアクセスの場所ごとに、古いファイルを**1回の検索**（`search.find`。最大5000件）で集め、フォルダごとに数・合計サイズ・大物（20MB以上）の数を集計する。大きさの検査（下限・上限）に通る、**いちばん上のフォルダ**だけを候補にする（通った場所の中の小さなフォルダは出さない）。
- 5000件で打ち切られた場所（大きすぎる）は、中のフォルダを1つずつ調べる。調べる回数は60回、時間は45秒まで。2分間は結果を覚えておき、選びなおしで調べなおさない。
- 見せるもの：場所・古いファイルの数・合計サイズ・大物の数・長さ（100体未満：短め／300体未満：ふつう／それ以上：長め）・AIの鑑定の回数。最大12か所、大きい順。
- 数は目安：最近使ったものや、アクセスの形跡があるものは、選んだあとの本番の調べで除かれる。そのため、本番の検査で断られることもある。
- 選んだ場所のIDは、選んだときに、クイックアクセスからたどって手に入れる（下の「実機で分かったこと：冒険の地」）。
- 候補が1つも無いときは、そう言って、自分で探す画面へ。一覧の最後の「自分で さがす」からも行ける。
- テスト：`unit.mjs`（集計・いちばん上だけ選ぶ・出発点がちがう候補のまとめ・説明の文）と、`play.mjs`（おすすめの一覧が出る・大きすぎる場所は出ない・選ぶだけで遊べる）。

**実機で分かったこと：冒険の地**
- 本体は、フォルダを「ファイルID＋パス」で受け取り、IDの合わないものは断る（`denied: id does not match`）。IDが分かるのは、クイックアクセスの項目と、検索で見つかった項目だけ。
- だから、ドライブ（`C:\`）や打ち込んだパスは、そのままでは調べられない（1.0.1 までは、読めないとして黙って飛ばしていた）。
- 直し方（`roots.js`）：IDの分かるクイックアクセスから出発して、検索で1段ずつ中へたどり、IDを手に入れる。画面は「フォルダを たどって えらぶ」と、「パスを入力」（クイックアクセスの中だけ）。調べる前に、保存してある冒険の地を、最新の場所とIDに直す（名前を変えた・動かしたフォルダも追いかける）。
- 10章の部でも、フォルダ選びはこの方法で作る。

## 9. 危ないところ（先に分かっていること）

- **`index.js` が長い**（約1700行）。画面を持たない計算は、別のファイルに分けた。画面とつなぐ部分（戦闘・町・メニュー）は、まだ `index.js` にある。
- **AIの返事は信用しない。** 鑑定の返事に「全部ゴミ」と書かれても、手元の判定の「守る」は下げない。守る側の判定は、AIの結果と手元の判定の高いほうを採る。
- **冒険者カードのコードは信用しない。** 友だちが貼ったコードでも、検査してから使う。能力は上限で切り詰め、文字は描くだけにする。
- **カードは分身であって、本人ではない。** 友だちがいま遊んでいるわけではなく、渡した時点の姿が来る。画面でも、そう分かる書き方にする。
- **保存の大きさ**：`ep.storage` は1つの値が1MBまで。`pool`・`appraisal` は上限（1500件）を超えたら古いものから捨てる。
- **ドット絵と文字の確認**は、画面なしのテストではできない。見本の画像（`file-quest-monsters-preview.png`・`file-quest-bosses-preview.png`）で確かめる。

## 10. 部：フォルダから生まれる冒険【案】

ねらい：**1つのフォルダが、1つの「部」になる。** 部は、そのフォルダの古いファイルから、町・ダンジョン・困りごと・ボスが作られる、ひとまとまりの冒険。終えると次の部へ進む。次の部は、別のフォルダを選んで始める。
**レベル・装備・持ち物・仲間は、部をまたいで続く。** 敵の強さは、章ごとに決まった範囲で、勇者のレベルでは変わらない（10.3）。フォルダが大きいほど、部は長くなる。
部ごとに、**その都度つくる大筋の物語（グランドストーリー）**があり、小さな物語（章ごとの出来事・困りごと）が集まって進む（10.6）。

（この大型更新の呼び名）部＝遊ぶ単位。第1部、第2部…は、終えた順の番号。いまの遊び方（自由探索）は、部の仕組みに置き換えて、残さない（10.8）。
前の案（忘却の王が出る、固定の7章の物語）は、取りやめた。

この章は案。12章の「決めること」が決まってから、決まった分だけ作る。

### 10.1 変えないこと
- 1章の6つは、そのまま守る。
- **部の材料は、いまの調べ方の結果（候補）だけ。** 最近のもの・使われた形跡があるもの・システムの場所・鑑定で守られたものは、候補に入らない。部を作るために、敵にできる条件は広げない。
- **部を進めるために、ファイルをごみ箱へ送る必要は無い。** ボスを倒すと「回収待ち」に入るだけ。「たすける」で戻しても、章は進む。ごみ箱へ送るのは、これまでどおり回収所の1か所だけ。
- フォルダの名前は、画面に出す（自分のPCの中だけ）。AIに送るのは、設定でオンにしたときだけ（今のとおり）。
- AIが無くても、部は全部遊べる。

### 10.2 部のなりたち
1. **場所を選ぶ。** いまの「冒険の地」の選び方（クイックアクセスから、フォルダをたどって選ぶ。6章の「実機で分かったこと：冒険の地」）のまま。ドライブの直下は、本体がIDを渡さないので選べない。
2. **調べる。** いまの調べ方と、安全の判定のまま。
3. **見込みを見せる。** 2.の前に、ゲームが先に調べて、**部になれる場所の候補と、その大きさの目安を一覧で見せる**（1.0.4で作った。6章「冒険の地の候補を、機械的に見つける」）。ユーザーは選ぶだけ。部ができたら、目安に「〇章・ボス〇体」を足す。
4. **始める。** 部のデータが作られて、保存される（以後は凍結。フォルダの中身が変わっても、筋は変わらない。戦う直前の再確認だけ、今のとおり）。
5. **章を進める。** 町で困りごとを受け、ダンジョンで片づけ、ボスを倒す。最後の章のボスを倒すと、殿堂入り。
6. **次の部へ。** 別のフォルダを選ぶ。進行中の部は1つだけ。途中であきらめて、別の場所で新しい部を始めることもできる（あきらめた部は、中断として残り、あとで続けられる）。

**部になる条件（決定）**：候補が **30体以上、かつ合計200MB以上、600体まで**。下限に届かない場所は「小さすぎて冒険にならない」、上限をこえる場所は「大きすぎる」と出す。しきい値は設定で変えられる。まずこの値で試して、通しプレイで直す。
上限があるので、部のダンジョンや章の数も、600体までを前提に作ればよい。検査は、AIを呼ぶ前にする（6章「AIの費用と、冒険の地の大きさ」。1.0.3で作った）。
「フォルダ全体の容量」は数えない。数えるのは、敵になれる候補の数と合計サイズだけ（調べた結果から、追加の調べなしで分かる）。

### 10.3 ボリュームと長さ
- **群れ**：候補を、置いてあるフォルダ（直下の親フォルダ）ごとに集めたもの。小さい群れは、近いものと合わせる。
- **章の数＝群れの数**（3〜7）。群れが3つに満たなければ、大きい群れをファイルの種類で分ける。8つ以上なら、数と大きさの合計が大きい順に7つ採る。
- **ボス**：その章の群れにある、20MB以上の古いファイル。**1章に最大3体**（大きいものから。階の深いほうへ置く）。20MB以上が無い群れは、その群れでいちばん大きいファイルが、ボスになる。
- **最終章のボス**は、部全体でいちばん大きなファイル「ぬし」。
- **敵の強さは、章ごとに決まった範囲で、勇者のレベルでは変わらない**（2026-10-23。実際に遊んだ声：『こちらの攻撃力に応じて 敵の体力が変わってしまうと、爽快感がなくなる』。前の案『そのときのレベルに合わせる』を、やめた）。
  - 部ぜんたいで、敵のレベルは 1 から Lmax まで（Lmax は 敵の数から：`5 + 敵の数/35`、6〜24）。章ごとに、その一部（章1が いちばん低く、最終章が いちばん高い。範囲は つづいている）。章の中では、小さいファイルほど低く、大きいファイルほど高い（`parts.js` の `levelRange`・`encounter.js` の `partEnemyLevel`）。
  - 勇者が育てば、前の章の敵は 弱くなり、ひとふりで たおせる。それが 育った実感になる。
  - 勇者が 遅れているときだけ、手に負えなくならないよう、敵のレベルの上限を つける（平均レベル＋3。ボスは＋4）。ボスは＋2、ぬしは＋3。ボスは、ひとりのときだけ やわらぐ（`bossEase`）。
  - 経験値とゴールドは、今のとおり 敵のレベルから計算する。章を進めるほど、1戦で もらう量が ふえる。
  - 部のないとき（小さすぎる冒険の地）は、ファイルの大きさ由来のレベルと、平均レベルの上限（＋1。ボスは＋3）の、小さいほう。
  - 数字は、`balance.mjs` で確かめる（敵のレベルと勇者のレベルの差ごとの勝率の表がある）。
- 長さの目安：章ひとつ20分前後。3章で約1時間、7章で約2.5時間。通しプレイで測って、直す。

### 10.4 ダンジョン（機械生成）
- 章ごとに1つ。**階の数は3〜5**（群れの大きさで決まる：小3・中4・大5）。迷路のような、歩いて探す形。
- **ジャンル**（形の作り方）：
  - 洞窟型：ぐにゃぐにゃした通路。
  - 塔型：四角い部屋を廊下でつなぐ。上へ登る。
  - 城型：広間と回廊が左右対称。
  - 沼・巣などは、最初は洞窟型の色違いにする。形を足すのは、あとで。
  - 群れの中身（いちばん多い種類）から決める。画像・動画は洞窟、書類・圧縮は塔、コード・実行は城。決まらないときは、群れのidから決める。
- **形は 7つ、階ごとに ちがう**（2026-10-23。実際に遊んだ声：形が 単調すぎる）。洞窟・塔・城・沼に、水たまりの洞窟（池が うかぶ）・迷路（せまい通路が 入りくむ）・大広間（柱の ならぶ広間と小部屋）・めぐる回廊（3重の輪）を足した。ジャンルごとに 形の組み合わせがあり、1階は そのジャンルらしい形、ほかの階は 組み合わせの中から 階ごとに ちがう形になる（洞窟：洞窟・池・迷路／沼：池・洞窟・迷路／塔：塔・回廊・迷路／城：城・大広間・回廊）。階に おりたときに、形ごとの ようすが 一言 出る。池は 通れず、まわりを歩いて 全部に着ける。見える範囲は、深い階ほど せまい。壁の たいまつ・床の小物は、ジャンルごとに ちがう。
- **生成**：シード（部のid＋章＋階）から決まるので、いつ入っても同じ形。作るたびに「入口から階段まで、歩いて着ける」ことを確かめ、ダメなら作り直す。
- 置くもの：上り下りの階段、宝箱（行き止まりに。ゴールド・道具・素材。装備は低い確率）、泉（HPとMPが戻る。中の階に1か所）、ボス部屋（最下階。ボスが複数のときは、深い階から順に置く）。
- 敵は、歩くと出会う（今の歩数による遭遇と同じ）。出どころは2つ。
  - ファイルの敵：その群れのファイル。倒すと回収待ちにたまる。
  - **まぼろし**：ファイルではない敵。ファイルが足りないとき（尽きたとき）に補う。倒しても回収待ちには入らない。強さは、平均Lv−1。経験値はふつうの敵の3割で、ゴールドとドロップは無し。（まぼろしを倒し続けて、いくらでもレベルを上げられないように）
- 名前：親フォルダの名前から作る（例：`Screenshots` → 「Screenshotsの洞窟」）。長すぎる名前・記号だらけの名前は、切り詰める。画面に描くだけ。
- 負けたら、その章の町に戻る。

### 10.5 町（機械生成）
- **町の数＝章の数。** 章ごとに1つ。その章の拠点になる。
- 手描きの「型」を4つほど用意する。章ごとに、型・色・建物の置き場所・人の置き場所を、機械的に変える。
- 建物：宿屋・道具屋・回収所・依頼所・酒場は、どの町にもある。鍛冶屋は、2章の町から。建物のドアに立つと、今の店の画面が開く。画面は今のものをそのまま使う。
- 町の人：依頼人（困りごとを持っている）と、うわさ話の人。名前と見た目は、機械的に決める。**町の人は、その町に住む人で、旅人ではない**（ダミーの旅人は作らない）。話は、ゲームの本当の状態（回収待ちの数・敵の数・遺跡の数）から作り、遊び方の手引きも兼ねる。いまは、案内役・回収所の番人・うわさ好きの3人。依頼人は、Step 12 で足す。
- 町の名前：名前の表から選ぶ（今の3つを増やす）。

### 10.6 物語＝部ごとにつくる大筋と、小さな物語の集まり【案 v3・要確認】

ねらい：物語は、**小さな物語の集まり**で進める。そのうえで、**部ごとに、その都度つくる「グランドストーリー」（大筋）**があって、小さな物語が、大筋の手がかりになる。部が変われば、筋が変わる。

**1. 構造**
- **グランドストーリー**：部に1つ。事件・ぬし・結末を持つ。
- **小さな物語**：章ごとに1つ。町で起きる小さな出来事（4文ほどで、ひとまとまりに終わる）と、ダンジョンのボス戦。そして、大筋の手がかりを1つ残す。
- **困りごと**：各章の町で2〜3つ。今の依頼の型（種類・合計サイズ・ボス・ぼうれい・勝利数）に、物語の言い回しをつける。
- **シリーズ**：部が続くと、前の部の続きになる。あらすじと、解決していない伏線を、次の部に引き継ぐ。そうじ屋（なんでも消したがる一味）・仲間は、部をまたいで出る。

**2. グランドストーリーを、その都度つくる**
- 部をつくる時点（章・ボス・ぬしが決まった直後）に、**物語の設計図**を1回つくって、部のデータに凍結する（あとで変わらない）。
- つくり方：AIが使えれば、AIに1回頼む。使えない・失敗・返事がおかしいときは、テンプレートから同じ形をつくる。**どちらでも、同じ形の設計図になる**ので、ゲームの側は、どちらでつくったかを知らない。
- 設計図に入るもの（全部で2KBほど）：題名・舞台の紹介・序（あらすじ）・ぬし（正体・動機・どんでん返し）・章ごと { 小さな物語（4文）・手がかり・町の人のひとこと・困りごとの文面 }・そうじ屋が出る章・結末3種（守る／手放す／両方）・次の部への引き（伏線）。
- **AIが決めないもの**：章の数・ボス・敵の数・報酬・封印の条件・敵の強さ。数と進行は、全部ルールが決める。AIが書くのは、文章と、「どの章で何が起きるか」の割りふり（章の番号は、範囲の中の整数だけ）。
- **AIへの材料**：舞台（フォルダの名前は、設定でオンにしたときだけ。オフなら「画像が多い場所」のような、種類のことば）・各章のダンジョンの型と、ボスのファイル名・拡張子・大きさ・作成年月・放置の年数・ぬし（同じ）・仲間3人の名前と役割と性格（固定）・勇者の名前とレベル・これまでのあらすじ（前の部から、3件まで）と、解決していない伏線（5件まで）。**ファイルの中身は、読まず、送らない**（今のまま）。
- **検査**：決まった形か・文字数（切る）・記号（除く）・章の数がそろっているか。足りない欄は、その欄だけテンプレートで補う。文字は画面に描くだけで、HTMLとして扱わない。
- **費用**：1つの部につき1回（出力は2000トークン前後）。AIを使わないときは、0。

**3. ぬしと、手がかり**
- 部でいちばん大きい古いファイルが「ぬし」（最終ボス）。名前・拡張子・大きさ・作った日（作成日時）から、正体の型を選ぶ（テンプレートの側の表。10種ほど）：「最終・final・v2・修正」→ 締切の亡者／「コピー・copy・(1)」→ コピーの双子／「無題・新しい・untitled」→ 名もなき旅人／「IMG・DSC・スクリーンショット」→ 写真の亡霊／「backup・バックアップ」→ 眠れる守り番、など。決まらなければ、拡張子の種類の型。AIでつくるときも、この型を材料として渡す。
- 作った日から「〇年前の夜に生まれた」、大きさから体の大きさ、放置の長さから「ずっと待っていた」、を語りに入れる。正体は、はじめは**伏せ字**で出る（「さ■■■のぬし」）。
- 章のボス（大物）を倒すと、「記憶のかけら」を落とす。かけらは、そのボスのファイルの実際の記録（作った年月・種類・大きさ）から作った、短い思い出話。かけらがたまると、ぬしの名前の伏せ字が開く。

**4. 4幕**（章の数が違っても、同じ割合で置く）
- 序：町に、ほこりが降りはじめた。小さな困りごとを片づけながら、ぬしのうわさを聞く。
- 展：ダンジョンの奥で、かけらを集める。ライバル「そうじ屋」と対立する。
- 転：仲間それぞれの過去が語られる（鑑定士は、昔「ごみ」と見まちがえて、大事なものを消した、など）。ぬしの正体の意外な面が明かされる（「実は、持ち主を待っていた」型・「実は、ぼうれいの親玉だった」型など）。
- 結：ぬしとの戦い。そのあと、**選ぶ**：倒して手放す／守りの印をつけて見逃す。

**5. 選ぶと、結末が変わる**
- 部の終わりの選択（ぬしや大物を、手放したか・守ったか）と、冒険のようす（回収した容量・「たすける」の数・そうじ屋への態度）で、結末のことばと、殿堂の称号が変わる。例：「思い出の守り手」「整理の達人」「ちょうどいい人」。
- どの結末でも、ファイルは勝手に消えない（戦ったら回収待ち、ごみ箱へ送るのは回収所の確認のあと、は変えない）。

**6. シリーズの引き継ぎ**：部を終えるたびに、あらすじ（100字まで）・結末・解決していない伏線を、シリーズの記録に足す（古いものは捨てる：あらすじ3件・伏線5件まで）。次の部の材料に入れるので、そうじ屋の動き・仲間の変化・前の部の結末が、次の筋に出る。

**7. テンプレート（AIなしで、遊べる品質）**：ぬしの型10種 × 小さな物語の型（数十）× そうじ屋のセリフ。手で書く量が多いので、はじめは型を少なめにして、あとで増やす。

**8. ワクワクを足すもの（順に）**：図鑑（倒した種類の一覧）・隠しボス（5年以上放置のぼうれい）・宝箱の「思い出の品」・称号のコレクション・仲間との掛け合い。

**9. 町・ダンジョン・島との関係**：町の人が、章ごとに、小さな物語と手がかりを話す（10.5）。ダンジョンは、階を進んで、奥でボス（かけらを落とす）に会う（10.4）。島は、部ごとに別（10.9）。

### 10.7 仲間と、引き継ぎ
- **部をまたいで、ぜんぶ続く**：レベル・経験値・HP・持ち物・装備・ゴールド・素材・仲間・絆・名前・見た目・カード・フレンド。部が変わっても、育てたものは、そのまま。
- **部ごとに新しくなるもの**：島・町・ダンジョン・依頼・位置・章の進み。
- 難しさは、そのときのレベルに合わせる（10.3）。育てたぶん、新しい部で簡単になりすぎない。
- 【取りやめ：2026-10-23】物語の仲間は固定の3人（ミナ：鑑定士・ガルド：前衛・リリ：回復）。第1部の章1・2・3の町で、順に加わる（加わったかどうかは、シリーズの記録に持つ。部をまたいで続く）。第2部からは、はじめから一緒（宿屋・仲間の画面で、同行を入れ替える）。第2部以降に、新しい仲間（盗賊など）が1人ずつ加わる案もある【任意】。
  実際に遊んだ人の声：勝手に旅人（ミナ）が仲間になるのは いらない。仲間は、酒場の友だち（冒険者カード）だけにする。
- **今の仲間の仕組みを、そのまま使う。** 新しい仕組みは作らない。加わった仲間は、ふつうのフレンドと同じ記録（種別が "story"）として `friends` に入る。同行・別れる・絆の段階とくぎ・おまかせの行動・パーティ最大4人は、今のまま動く。レベルは今のNPCと同じ（ヒーローのレベル−1）。
- 同行3人の枠は、友だちの分身（盗賊もここ）と分け合い、酒場と「仲間」の画面から入れ替える。
- 友だちの分身は、今のとおり酒場。カードのレベルは「ヒーローのレベル+2」で切られる。

### 10.8 いまの遊び方（自由探索）は残さない
- いまの遊び方（フォルダを選んで、島を歩き回って戦う）は、部の仕組みに置き換える。章のない部は作らない。
- **今のセーブは、そのまま引き継ぐ**（勇者・持ち物・仲間は、部をまたいで続くので、捨てない）。部の記録は、空から始まる。
- 作りかけの間（Step 12 まで）は、部が1つも無いときは、いまの遊び方のまま動く。部が遊べるようになったら（Step 12）、「部をはじめる」に置き換える。

### 10.9 部のデータと、足せる作り
考え方：**エンジン（部に関係ない仕組み）と、部（データ）を分ける。** 部は、生成器が作るデータ。手で書いた部（`packs/partN.js`）も、同じ形で読める【任意】。

**部のデータ**（作った時点で凍結して保存）
```
def { id, kind: "folder"|"hand", 元のフォルダ, シード, 作った日,
      島 { 町の数＝章の数, ダンジョンの数 },
      章 [ { 町 { 型, 名前, 建物, 人 }, ダンジョン { ジャンル, 階数, 群れのファイル }, ボス [ファイル], 困りごと [ … ], 台本 } ],
      ぬし（最終ボス）,
      物語 { 題名, 序, ぬし { 正体, 動機, どんでん返し }, 章ごと [ { 小さな物語, 手がかり, 町の人, 困りごとの文面 } ], そうじ屋の章, 結末 { 守る, 手放す, 両方 }, 引き } }   # 設計図（10.6）。つくった時点で凍結
```
- ファイルへの参照は、今の候補（pool）と同じ形（id・path・サイズ・時刻）。戦う直前に、今のとおり再確認する。**参照先が消えた・使われた・守られたときは、その枠をまぼろしに置き換える**。章は止まらない。
- 場所は、名前（部のid＋章＋種類）で指す。番号では指さない。島は、部ごとに別（シードは「部のid＋セーブのシード」）。前の部の島は、作り直さない。
- **第N部を足す＝別のフォルダで、新しい部を始めるだけ。** コードは直さない。手書きの部を足したいときだけ、`packs/` に1ファイル書いて、`packs/index.js` に1行足す。
- 台本の命令は、小さな決まったものだけ（話す・旗を立てる・仲間が加わる・道具を渡す・戦う・店を開く・移動する）。

**セーブ（v3）**
```
save（いまの中身：lv・exp・gold・inv・equip・friends・cards・look … は、そのまま。部をまたいで続く）に、次を足す
  series { done [ { id, 題名, あらすじ（100字まで）, 結末, 日 } ]（終えた部。殿堂。あらすじは3件まで）,
           threads [ 伏線 ]（5件まで）, joined { <仲間のid>: true } }
  active: <部のid> | null
  parts { <部のid>: { def: {…凍結した部のデータ…},
                      loc: { map, kind: "world"|"town"|"dungeon", id, floor, x, y },
                      progress: { chapter, flags, dungeons { <id>: { cleared, chests [] } } } } }      # 部ごとの記録だけ
v2 → v3：いまの save に、series・active・parts を足すだけ（ほかは、そのまま）
```
- 主人公の状態は、いまの `save` のまま（部の中には入れない）。`index.js` の書き換えは小さい。
- 知らない種類の部の記録は、消さずに残す。

### 10.10 AIの役目
- **部ごとの物語の設計図**を、AIに頼める（10.6）。1つの部につき1回。文章と割りふりだけ。数と進行は、ルールが決める。AIが無くても、テンプレートで同じ形ができる。
- 町の人・ボス・かけらの語りは、設計図の中に入っているので、遊んでいる最中の、AIの呼び出しは増えない。
- 今まで通り使うもの：二つ名・敵の技・鑑定・依頼・日誌。依頼文の言い換えには、困りごとの言い回しを渡す（検査してから使う）。日誌には、部の名前を足す。

### 10.11 危ないところ
- **フォルダの中身は変わる。** 部は作った時点で凍結し、戦う直前に再確認する。消えた・使われたファイルは、まぼろしで補う。
- **群れが偏る。** 1つの群れにほとんどが入る、巨大なファイルが1つだけ、などは、ファイルの種類で分ける・ボスを1体にする、で受ける。通しプレイを、いろいろな形の偽のフォルダで流して確かめる。
- **まぼろしで経験値を稼げてしまう。** 経験値を3割にし、ゴールドとドロップを無しにする。バランス計算で、まぼろし稼ぎが、ふつうの敵より遅いことを確かめる。
- **AIの物語が、おかしい（長すぎる・形がちがう・不適切）。** 検査して、足りない欄をテンプレートで補う。物語の進行（数・封印・報酬）は、ルールが決めるので、AIの返事で遊びが壊れない。
- **育てるほど簡単にならないが、強くなった実感が薄くなる。** 敵がレベルに合わせて強くなるので、実感は、装備・仲間・とくぎで、戦い方が楽になること、で出す。バランス計算で、Lv1・10・30・50 を確かめる。
- **シリーズが長くなると、引き継ぎが増える。** あらすじは3件まで、伏線は5件までに切る。
- **機械生成は、平らになりやすい。** 形を少数に絞り（ダンジョン3・町4）、丁寧に作る。台本のテンプレートは多めに書く。
- **長さの見積もりが、実際と合わない。** 通しプレイで章あたりの時間を測り、しきい値を調整する。
- **調べに時間がかかる。** 広いフォルダでは、今の調べ方でも時間がかかる。進み具合の表示は、今のとおり。調べた結果は保存して、「部にならない」場所でも、無駄にしない。
- **セーブの変更は、足すだけ**（series・active・parts）。主人公の状態は、そのまま。移行のテスト（v2 → v3）は通す。
- **`index.js` が大きい**（約1900行）。部に入る前に、画面の部品を `ui.js` に出す。
- **実機で遊んでいない。** 1.0.0 を実機で遊び、直すところを直してから、Step 8 に入るのが安全。
- **安全：** ボスや町の人にも、ファイルの扱いは今の安全の判定を必ず通す。部の材料は候補だけ。
- **ボス戦は、ひとりでは勝てなかった**（`balance.mjs` のボス戦の計算：ソロの勝率は Lv1 で0.1%・Lv5 で21%・Lv20 で3.5%。2人以上なら、Lv1 で91%・Lv5 以上で96〜99%）。章を進める関門なのに、仲間は友だちのカードだけなので、**ボスは、ひとりのときだけ やわらげる**（`bossEase`：HP62%・こうげき90%。ソロの勝率は Lv1 で81%・Lv5〜20 で94〜97%・Lv50 で86%）。遺跡に ひとりで入るときは、仲間と行くと楽だと知らせる。
- **部のはじまり：** 冒険の地を調べて新しい部ができると、そのまま はじまりの町に入って、章1の物語とミナが加わる（町の外に立ったままにしない）。

### 10.12 デバッグ機能（進行度のリセット）【一部済：1.0.1】

ねらい：作りながら、何度でも最初からやりなおして試せるように。

**出し方**：設定「デバッグ機能を使う」をオンにすると、コマンド（Ctrl+Shift+P）に出る。ふだんは出ない（まちがえて押さないように）。

**種類**
| コマンド | 戻るもの | 残るもの |
|---|---|---|
| デバッグ：進行度をリセット | レベル・経験値・持ち物・装備・素材・ゴールド・依頼・位置・フレンドの絆と同行 | 調べた結果（敵の候補）・回収待ち・助けたファイル・冒険の地・世界の形・カード・フレンド・名前 |
| デバッグ：進行度をリセットして調べなおす | 上に加えて、回収待ちと助けたファイルの一覧。敵を集めなおす | 冒険の地・世界の形・カード・フレンド・名前 |
| 最初からやりなおす（ふつうのコマンド） | 上に加えて、冒険の地・カード・フレンド・名前。はじまりの会話から | 世界の形 |

**決まり**
- **動いているゲームの中身を入れかえて、すぐ保存する。** 保存だけ消すと、次の自動セーブで元に戻ってしまう（1.0.0 の「最初からやりなおす」には、この問題があった）。
- 会話・戦闘・メニューの最中は、断る（「いまは使えません」）。
- ファイルにも、ごみ箱にも触らない。実行の前に、確認を出す。

**部ができたら広げる**（Step 8 以降）
- 進行度をリセット：今の部の、章・旗・ダンジョンの進みと、主人公を最初に戻す（部のデータは変えない）。
- 今の部を作りなおす：フォルダを調べなおして、部のデータを作りなおす（筋も変わる）。
- 殿堂を消す。全部消す。

**テスト**：`unit.mjs`（`reset.js`：何が戻り、何が残るか）と、`play.mjs --reset`（実行中に3つのコマンドを呼び、中身が入れかわる・調べた結果が残る・しばらく遊んでも保存が元に戻らない）。

## 11. 部の実装ステップ【案】

各ステップの最後に、画面なしの通しプレイと部品のテストを通す。ステップごとに、版を上げる（Step 8〜9：1.1.0、Step 10〜11：1.2.0、Step 12〜13：1.3.0、Step 14：2.0.0）。

**順番の推奨（実機で遊んで分かった、物足りない順）**：①Step 8（土台）→ ②Step 10（ダンジョン。いまは入った瞬間にボス戦。階を歩く迷路にする）→ ③Step 11（歩ける町。いまはメニューが出るだけ）→ ④Step 9（部の生成。島が部ごとに変わる）→ ⑤Step 12（物語。10.6の案 v2）→ ⑥Step 13・14。体感の変化が大きい、ダンジョンと町を先にやる。勇者の見た目（3.8）は、Step 8 より前に、1.0.6 で済ませた。

### Step 8　土台：マス目の場面とセーブ v3【済：1.1.0】
- 画面の部品を `ui.js` に出す。地図の歩き方を `grid.js` に出して、地図・町・ダンジョンで共通に使えるようにする。セーブを v3 にする（いまの save に、series・active・parts を足すだけ。主人公の状態は、そのまま）。部が1つも無いときは、いまの遊び方のまま動く。場所を名前で指す仕組みを作る。**敵のレベルの規則を、平均Lvに合わせる形に直す**（10.3。Lv20をこえても弱くならない。序盤の手ごたえは、今のまま）。島を作る関数に、町の数とダンジョンの数を渡せるようにする。
- デバッグのリセット（10.12）は、1.0.1 で先に作った。ここで、部の単位に広げる。
- 受け入れ：いまの遊び方が、今とまったく変わらず動く（序盤の手ごたえも）。古いセーブが、そのまま読める（勇者・持ち物・仲間も）。Lv30・50 でも、敵が弱いままにならない。
- テスト：`unit.mjs` が通る。`play.mjs` の全モード（`--reset` を含む）が、今と同じ結果で通る。v2 → v3 の変換のテスト。
- 結果：`ui.js`（描画・文・選択の部品）・`grid.js`（歩き方・カメラ・歩数の地図）を出した。セーブは v3（`series`・`parts`・`activePart`・`dgState`・`loc`・`look`・`islandSeed` を足しただけ。進行中の部を指すのは `activePart`。`active` は依頼の一覧のまま）。敵のレベルは `enemyLevel`（Lv10までは従来どおり、それをこえた分だけ足す）。`generateWorld` は町と遺跡の数・名前を渡せる。

### Step 9　部の生成（画面なし）【済：1.2.0。部の保存と島への反映は Step 12 で】
- `parts.js`：候補から、群れ・章・ボス・ぬし・困りごとの型を作る。部になる条件の判定。「見込み」の画面（章の数・ボス・長さ）。
- 受け入れ：場所を選ぶと、見込みが出る。小さすぎる場所は、そう出る。
- テスト：偽の候補を、いろいろな形で作って流す（ちょうどしきい値・巨大1つ・全部同じフォルダ・種類が1つだけ・大量）。どれでも、章が3〜7で、全部の章にボスがいて、同じ入力なら同じ部ができる。
- 結果：`parts.js`。群れ＝置いてあるフォルダ。小さい群れ（全体の6%未満、または4個未満）は、置き場所の近い群れに合わさる。8つ以上なら大きい順に7つ。3つに足りなければ、いちばん大きい群れを、種類・大きさ・ファイル名のハッシュの順で分ける。群れの中身は、決まり（置き場所＋種類・大きさ・ハッシュ）で持つので、保存は小さく、ファイルが増えても、前のファイルの章は変わらない。章は、いちばん大きいファイルが小さい順（だんだん強く）。ボスは、20MB以上を大きいものから最大3体（なければ最大の1体）、小さい順に（深い階ほど大きい）。ぬしは、部で最大のファイル＝最終章の最後のボス。ダンジョンの型は、種類から（画像・動画：洞窟／書類・圧縮：塔／コード・実行：城／音楽：沼）、階数は群れの数から（12個まで3階・40個まで4階・それより多いと5階）。名前は、フォルダ名から（記号・かっこを除く。重なれば種類を足す）。見込みは、調べた一覧の集計だけで出る（候補の説明に『4章　ボス5体　およそ1時間20分』）。まぼろしの敵の型（`phantomFor`）もここ。

### Step 10　ダンジョンの生成と場面【済：1.2.0。まぼろしは Step 9 と一緒に】
- `dungeon.js`：洞窟・塔・城の3ジャンル、3〜5階、つながりの検査、宝箱・階段・泉・ボス部屋。ダンジョンの場面（マス目）、まぼろし。
- 受け入れ：ダンジョンに入って、最下階のボスまで着ける。どのジャンルでも迷子にならない。
- テスト：シードを何千通りも変え、全ジャンル・全階数で、入口から階段・宝箱・ボス部屋に歩いて着くことを確かめる。
- 結果：`dungeon.js`（階の作りは、島の種と遺跡の番号だけで決まる。ジャンルは城・洞窟・洞窟・塔・沼で、沼は洞窟と同じ形。幅優先の検査で、階段・宝箱・泉・ボスへ必ず歩いて着ける。宝箱の中身にファイルは入らない）と、`index.js` のダンジョンの場面（暗がり・ミニマップ・階の移動・宝箱・泉・ボス・ランダムエンカウント）。宝箱は階ごとの番号で覚え、開けた箱はつぎに入っても空。深い階ほど、大きなファイルが出る。ボスに負けたら町に戻り、『いる場所』の記録を消す。島を作りなおす・最初からやりなおすときも、ダンジョンの外に出す。
- ボットの確かめ：`play.mjs --dungeon`（`--god`・`--lv`）で、入る・下りる・宝箱・泉・ボスを倒す・負けて外に出る、までを通した。ファイルの敵が尽きたあとにボスの前に立つと『もう だれもいない』と外に出る。これは、まぼろし（Step 9）で直す。

### Step 11　町の生成と、歩ける町【済：1.2.0】
- `town.js`：手描きの型4つ、建物と人の置き場所、ドアから今の店の画面を開く、出口。
- 受け入れ：町に入ると歩ける。ドアに立つと店が開き、閉じると町に戻る。
- テスト：どのドアも知っている店につながる。出口と全部のドアに、歩いて着ける。人が壁に埋まっていない。
- 結果：`town.js`（型は、広場の町・川の町・まるい村・みなとの町の4つ。島の種と町の番号から、型・色・建物の並び・人の名前と姿・木と花が決まる。同じ島の町は、4つまで型が重ならない）。建物は6つ（宿屋・道具屋・鍛冶屋・依頼所・回収所・酒場）で、屋根の看板に絵と名前。ドアに立つと店が開き、閉じると町に戻る。向いている人に Enter で話しかける。南の出口で世界地図へ。いままでの町のメニューは、なくした。町の中は保存しない（閉じたら、世界地図の町の上から）。鍛冶屋を2章の町から、は Step 12 で。
- 試験：`unit.mjs` で、4つの型×何百もの種で、出口から全部のドア・出口・人のとなりに、人をよけて歩いて着けること／建物がちょうど6つ・重ならない／同じ入力は同じ町。`play.mjs` で、ボットが町を歩いて店に入り、人に話しかけること。`sprites.mjs` が、町の見本画像（`file-quest-towns-preview.png`）を作る。

### Step 12　困りごと・章の進行・殿堂【済：1.3.0】
- `story.js`：**物語の設計図**（10.6。AIで1回／テンプレート。同じ形。検査して、凍結する）・困りごと。受ける・片づける・封印が解ける・ボスを倒す・章が進む・最終ボス・殿堂入り。種別は "story"。10.7）。
- 設計図の検査のテスト：AIの返事が、壊れている・長すぎる・章の数が合わない・欄が足りない・記号だらけ、のどれでも、必ず、テンプレートで補われて、同じ形になる。AIなしでも、1部が最後まで遊べる。
- 受け入れ：部を最初から最後まで遊べる。ファイルの敵が尽きても、まぼろしで進める。（物語の仲間は、取りやめ）
- テスト：偽のフォルダ（小・中・大）で、ボットが通す（`play.mjs --parts`）。小は3章、大は7章で終わる。ボスを倒しても、ファイルが回収待ちに入るだけで、ごみ箱は触らない。
- 結果：`story.js`（ぬしの型11種・小さな物語のテンプレート・かけら・結末・AIの返事の検査と重ね書き。AIは、題・序・章ごとの文・結末・引きだけ書ける。数・進行は決められない。フォルダ名は設定でオンのときだけ渡す）、`campaign.js`（封印・ボスの階・かけら・章と部の完了）、`parts.js` の `cleanDef`（保存した部の検査）、`index.js`（部の開始と続き・島を部に合わせる・封印・章のファイルだけの敵・まぼろし・階段を守るボス・かけら・結末と殿堂・物語の窓・町の人の話・困りごとの言い回し）。保存は、部ごとに本体・進み・物語を持つ。
- 試験：`unit.mjs` で、部・物語・進み方・保存の検査（偽のフォルダ14種×何通りも）。`play.mjs --campaign`（AIあり・なし・壊れたAI・`--keep`・`--next`）で、ボットが 部を最後まで通す（章が終わるたびに封印が解け、仲間が3人加わり、ぬしを倒して結末を選び、殿堂に入る）。
- まだ：鍛冶屋を2章の町から（いまは、どの町にもある）、そうじ屋との対決（いまは台詞だけ）、依頼人としての町の人（いまは依頼所の困りごと）、図鑑・隠しボス（10.6の8）。

### Step 13　部のまたぎ【一部済：1.3.0】
- 次の部を選ぶ・あきらめる・中断から続ける、最初からのやり直し、殿堂入りと、シリーズの引き継ぎ（あらすじ・伏線）。部が1つも無いときの、いまの遊び方を消す。レベル・持ち物・仲間は、部をまたいで続く（そのまま）。
- 受け入れ：部を終えて、別のフォルダで新しい部が始まる。レベル・持ち物・仲間は、そのまま続く。
- 結果：部を終えたあと『つぎの 冒険の地を えらぶ』で、新しい部を始められる（ファイルのメニューからも、いつでも）。同じ冒険の地を選ぶと、同じ部の続き。前の部は中断として残る（12まで）。殿堂のあらすじ3件・伏線は、次の部の物語の材料に入る。部が つくれないほど小さい冒険の地だけ、部なしで遊ぶ（遺跡のボス＝いちばん大きい敵）。
- まだ：部の一覧から選んで続ける・あきらめる画面。
